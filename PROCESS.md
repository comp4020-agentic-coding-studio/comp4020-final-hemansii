# Process overview

The Dig became a shared archaeological investigation. Visitors receive five free digs per day, expose and brush sections, save useful fragments to a private specimen tray, leave field notes and build theories from evidence. When a buried early-2000s website is solved, the shared excavation moves to the next one.

## Stack and agent workflow

The course deploys the app to one Fly machine with one persistent volume, so I chose SQLite on that volume rather than introducing another database service. With one process, the in-process event bus can reach every open SSE session, and better-sqlite3 lets the check and write for a dig happen inside one synchronous transaction. That keeps first-write-wins simple and testable. The trade-off is that this architecture does not scale directly to multiple machines: the event bus would need shared infrastructure and SQLite would need a different coordination strategy. For this project size, I preferred the simpler single-source-of-truth design. The SSE race decision and its alternatives are recorded in `docs/decisions/0001-live-same-cell-race.md`.

My agent workflow used specifications as durable constraints rather than relying only on prompts. At the start of Crit 8 I had the persistence requirement written as an intentionally red test ([1fd9096](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/1fd9096)), then implemented until persistence, daily-limit and no-spoiler checks went green ([23a4d69](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/23a4d69)). I kept using automated checks for rules the server could enforce, then browser checks and explicit acceptance criteria for behaviour or visual judgement the tests could not capture.

## From persistence to a live shared world

Crit 8 established persistence. Crit 9 made the same world live. I kept the server-rendered architecture and added server-sent events rather than moving to WebSockets or a client framework. Successful digs, brushes, notes and theories are broadcast to connected visitors. If two people try to dig the same section, the server keeps a first-write-wins rule and the second visitor is told someone else got there first.

The first live version worked but still felt silent. I directed the agent to make other players visible through names, activity and notifications, while collaboration actions updated in place ([f5db69b](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/f5db69b68bc1a23f0c47a09d4b546b38c79d0203), [bb677b2](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/bb677b2217b83132b529697ffc04e7b39db7b875)).

That introduced failures automated checks did not reveal. Settled tiles replayed animations during live updates and visibly flickered. I caught that in the browser and had the update logic changed so only newly changed content animates ([ca51929](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/ca5192904dbdd1dfecc4597d5d2fe10469205a30)). Later mobile testing exposed that the desktop interface had effectively been shrunk rather than designed for touch. I directed a mobile-specific pass with a clearer status card, pannable excavation viewport and tap-versus-drag handling ([c7539a8](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/c7539a82e8f8d33018cb7cd4982dee91163fbc82)). A slow connection then exposed a race where a repeated tap could look like another player reaching the same tile, which was corrected separately ([0cad4d2](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/0cad4d2c98c853aaa795b812c1bd1b0903adf2e3)). The final interaction pass taught the sequence `dig -> brush -> save`, stopped settled tiles replaying animations and cleaned the specimen detail card ([10f2469](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/10f24692be64375b5b952923c26e3cad715dae80)).

## Visual and evidence design

Earlier versions looked like dashboards rather than one excavation site. I moved the design toward a connected isometric dig and supplied archaeology asset sheets for terrain, tools and props ([6834160](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/68341603d035b0cbd56f73dc59b2cdc96f32b06b), [502bac3](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/502bac3423866bde978097ea1d91cf9fdec22af7)). I also rejected visual details that did not fit, such as shadows that made props appear to float ([384c436](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/384c436649b25145405ebe39dc39fd8580df4a19)).

The specimen tray became an evidence space for private notes and finds cited in public theories ([ccce972](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/ccce972aeaeb60593de563c5658f213502273842), [8631798](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/8631798f560fa4cb36991087b1122ae1acddab91)). The game also moved from one fictional homepage to recognisable sites including Club Penguin, MySpace, Neopets, Bebo and Miniclip ([d041e68](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/d041e682611cd2757bcc3870043dc9fef22610f6)).

## Identity, authorisation and observability

Crit 10 made me separate presentation identity from server identity. A visitor's cookie id is the real identity; the chosen name is only a label. Shared excavation actions, notes and theories are public, while specimen trays and private specimen notes are scoped to their owner. I documented those rules in `docs/decisions/0002-what-a-visitor-may-see-and-change.md` ([7c5cfdd](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/7c5cfdd701da698eb5d50244e40ab7a533fc9c8c)).

I also added structured server-side audit logging for every state-changing action. Each log records the action, target, result, display name and a stable hashed visitor reference without exposing the raw cookie ([9f99701](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/9f99701c1a003c4ac2791b1a50635b03bbd16ed4)). This made it possible to narrate separate browser sessions from Fly logs without relying on my own UI.

## Final product pass

The final weeks focused on strengthening the existing game rather than expanding it. I added History, daily trivia, shards and bonus digs ([5d5db28](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/5d5db28fea7d4c9517597503b1845db855cd3def)), then a live presence count ([649d5db](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/649d5dbb13f228b54fc10597c49a513757934447)).

Before submission I asked the agent to act as a product manager and produce lightweight personas, PRFAQs and a RICE ranking using reach, impact, confidence and effort. The personas were assumptions based on the product, not user interviews. I used the exercise to compare possible improvements, not as an automatic roadmap.

The clearest example was "theories need evidence". The planning pass had already identified the loophole that one theory containing all five site names could solve any open site, but the feature label itself was unclear. I asked what it meant and then directed the implementation with explicit acceptance criteria: ordinary hunches should still post, solving should require one correct site name plus evidence from that visitor's own tray, evidence must be checked server-side, the player should get clear feedback when a correct guess lacks evidence, and a test should prove that listing all five names cannot bypass the rule. That became [8135575](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/813557569f0a7aafa6d92c9e994cfabfd3009b68).

RICE ranked the reset countdown and reconnect state highly, and both were implemented ([548644e](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/548644ecc81eb83c3167a492abfa56b9bf46709a), [ddc69bd](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/ddc69bd1b256e773329709fc97b470f829f2f474)). It placed "Since you last dug" and contributor credit after submission, but I chose to build them too after the higher-priority fixes were stable because they directly reinforced the persistent, collaborative premise without opening a separate product area ([597fe4d](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/597fe4d36df9fc255f1478d7d8ddc5d86f22fe7c), [2b81c73](https://github.com/comp4020-agentic-coding-studio/comp4020-final-hemansii/commit/2b81c7399e6ce61b1f8e9c186117a710f2e12d6d)). I still rejected lower-priority ideas such as cross-device identity and adding more sites. This made RICE useful as a discussion tool rather than a rule.

## Verification and what changed in my process

Corrections mostly ended up in `spec/` rather than in a growing prompt file. `CLAUDE.md` stayed intentionally small and mainly carries the standing no-em-dash rule. More durable behaviour was enforced through tests and server checks.

The final suite covers persistence, dig limits, no-spoiler rules, live delivery, presence, identity, private evidence, audit logging, evidence-backed solving, reset timing and contributor credit. I also used `scripts/stress.ts` to exercise concurrency, including many visitors racing the same action and a 20-player solve race that must still produce exactly one winner.

My process shifted from asking whether the agent had completed a feature to asking what evidence justified accepting it. The strongest improvements came from grounding its work in the repository, correcting assumptions, defining acceptance criteria and checking deployed behaviour rather than trusting a confident summary.
