# Final project reflection

The biggest breakthrough in this project was changing how I used the coding agent. Earlier in the semester I was mainly asking whether a feature had been implemented. By the final project, I was instead defining what evidence would make me accept it. That became especially clear with the theory-solving rule. The original implementation and its test both passed even though a player could list all five website names and solve any site. A separate product-review pass exposed the loophole, and I then defined the acceptance criteria: hunches could still be posted, evidence had to come from the player's own tray, the server had to verify it, and listing every answer could not solve the site. The same approach shaped the concurrency tests, browser checks, mobile revisions and final usability work.

This project changed what I want to be as a software developer because I now see directing an agent as an engineering responsibility rather than simply a faster way to produce code. I still want agents to do substantial implementation work, but I want to be the person who defines the constraints, questions assumptions and decides what evidence is strong enough to ship. The most useful improvements often came after something was technically working, when I tested it in the browser, had friends try the mobile interaction, or compared the implementation against what the product was actually supposed to do. I want that habit of verification and deliberate acceptance to remain part of how I build software.
